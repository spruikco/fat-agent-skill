# Squarespace -- Platform Fix Reference

Squarespace is a fully hosted website builder. There is no server access, no
editable templates on version 7.1 (the current platform), and almost no
control over HTTP response headers. Fixes happen in four places:

1. **Page settings** -- each page has SEO fields (title, description), a URL
   slug, a social image, an option to hide the page from search engines, and
   a per-page header code injection area.
2. **Site-wide SEO settings** -- title format patterns for pages, collection
   items and products, plus the site description.
3. **Advanced settings** -- **Code Injection** (site-wide header and footer),
   **URL Mappings** (redirects), SSL / HSTS, and crawler settings.
4. **Commerce and collection settings** -- product and blog post SEO fields,
   and the URL format for blog posts.

Code injection is only available on the higher-tier plans (not the
entry-level plan). Check the client's plan before recommending any fix that
depends on it.

This reference covers the most common FAT Agent findings on Squarespace
sites. Squarespace renames panels fairly often; where an exact label is
uncertain, the area of the settings is described instead.

## Titles and Meta Descriptions

### Per page

Open the **Pages** panel, click the gear icon on a page, and go to the
**SEO** tab:

- **SEO title** -- overrides the page title in search results.
- **SEO description** -- the meta description.
- **URL slug** is in the **General** tab. Changing it on a live page does
  *not* always create a redirect, so add a URL Mapping yourself (below).

Blog posts, events and products have the same SEO fields in their own item
settings (the SEO tab of the post or product editor).

### Title format patterns

The site-wide SEO settings define how titles are assembled for each content
type, using variables:

```text
Pages:            %p | %s
Collection items: %i | %s
Products:         %i | %s
```

Where `%p` is the page title, `%i` the item title, and `%s` the site title.

Common FAT findings and fixes:

| Finding | Cause | Fix |
|---------|-------|-----|
| Home page title is just the brand | Home page has no SEO title | Add a descriptive SEO title on the home page (brand plus what you do plus location) |
| Titles over 60 characters | Long site title appended to every page | Shorten the site title or remove `%s` from the item pattern |
| Duplicate descriptions | SEO description left empty, falls back to site description | Write per-page descriptions for every indexable page |
| Duplicate titles on blog pagination | Squarespace uses the same title for `?offset=` pages | Platform limitation; ensure the first page has a strong title and rely on canonical |

## Canonicals and Duplicate URLs

Squarespace outputs a self-referencing canonical on every page and you cannot
change it per page. Do not inject a second canonical via code injection;
two canonicals are worse than one.

Where Squarespace creates duplicate or near-duplicate URLs:

- **Blog and product category / tag filters:** `/blog?category=News`,
  `/shop?tag=sale`. These are query-parameter views of the collection.
- **Pagination:** `/blog?offset=1700000000000`.
- **Format parameters:** `?format=json`, `?format=rss` and similar, which
  Squarespace exposes on collections.
- **The built-in `.squarespace.com` subdomain:** once a custom domain is
  primary, Squarespace redirects the built-in domain, but check it.

What you can do:

- Keep internal links pointing at clean URLs (no `?category=` in navigation
  unless the filtered view is a deliberate landing page).
- If a category view needs to rank, build a real page for it instead
  (a page with its own content and a summary block filtered to that category).
- Squarespace's own `robots.txt` already disallows several internal paths and
  parameter patterns. You cannot add to it (see below).

## robots.txt and noindex

### noindex a page

In the page's settings, turn on the option to **hide the page from search
engines** (in the SEO tab). Squarespace adds a `noindex` robots meta tag and
removes the page from the sitemap. Use it for thank-you pages, landing pages
built for ads, and duplicate content you cannot delete.

For finer control on a single page (for example, `noindex, follow`), use the
page's own header code injection (page settings > **Advanced**):

```html
<meta name="robots" content="noindex, follow">
```

Only use one method per page, otherwise you may output two robots meta tags.

### robots.txt

**You cannot edit robots.txt on Squarespace.** The file is generated by the
platform and blocks internal paths such as configuration, search and API
endpoints. The only related control is the crawler setting that lets you
block known AI crawlers (found in the site's crawler or SEO-related settings).
Decide deliberately: blocking AI crawlers can reduce visibility in AI answer
engines.

If a FAT finding needs a `robots.txt` change (for example, blocking a
parameter pattern), the workaround is a `noindex` meta tag on the affected
page, or accepting it as a platform limitation.

## 301 Redirects (URL Mappings)

Found in **Settings > Advanced > URL Mappings** (the path may differ slightly
by account). One rule per line:

```text
/old-path -> /new-path 301
/old-page -> https://other-site.com/page 301
/promo -> /shop/summer-sale 302
```

Squarespace also supports simple variables, which make migrations far
easier:

```text
# WordPress-style dated posts to Squarespace blog
/[year]/[month]/[day]/[slug] -> /blog/[slug] 301

# Old product folder to Squarespace shop
/product/[slug] -> /shop/p/[slug] 301

# Old category archive
/category/[name] -> /blog?category=[name] 301
```

Rules and limits:

| Behaviour | Detail |
|-----------|--------|
| Syntax | `/from -> /to 301` (or `302`); spaces around `->` matter |
| Variables | Bracketed names like `[slug]` capture a path segment |
| Order | Top-down, first match wins; put specific rules above variable rules |
| Only fires on missing URLs | A mapping does not override a page that currently exists at that path |
| Line limit | Capped (a few thousand lines); consolidate with variables for big migrations |
| Trailing slashes | Test both `/old-page` and `/old-page/`; add both lines if needed |
| Domain redirects | www / apex and HTTP to HTTPS are handled by the domain and SSL settings, not mappings |

Verify every mapping after saving:

```bash
curl -sIL https://www.example.com.au/2024/06/01/old-post | grep -Ei '^(HTTP|location)'
```

## Sitemaps

Squarespace generates `/sitemap.xml` automatically, including pages, blog
posts, products, events and images.

- **Cannot** edit it or add custom URLs.
- Pages hidden from search engines are excluded.
- Disabled pages and password-protected pages are excluded.
- Submit `https://www.example.com.au/sitemap.xml` in Search Console.

If FAT reports that the sitemap includes pages that should not be there, hide
those pages from search engines. If it reports missing pages, check they are
enabled, not password-protected, and not in the "Not linked" section with the
search visibility off.

## Structured Data

### What Squarespace generates

Squarespace outputs JSON-LD for the website and organisation (populated from
the site's business information), `LocalBusiness` details if the business
address and hours are filled in, and item-level markup on products, blog posts
and events. Fill in the business information settings completely before
adding any custom schema; it is the cheapest fix available.

Always check the output first with Google's Rich Results Test so you do not
duplicate what the platform already emits.

### Adding custom JSON-LD

Use **page-level header code injection** for schema that belongs to one page,
and **site-wide header code injection** only for schema that is valid on every
page.

LocalBusiness on the home or contact page (if the platform's own output is
incomplete):

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BeautySalon",
  "name": "Example Studio",
  "url": "https://www.example.com.au/",
  "telephone": "+61 8 8000 0000",
  "image": "https://images.squarespace-cdn.com/content/your-image.jpg",
  "priceRange": "$$",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "45 Example Road",
    "addressLocality": "Norwood",
    "addressRegion": "SA",
    "postalCode": "5067",
    "addressCountry": "AU"
  },
  "openingHoursSpecification": [
    {
      "@type": "OpeningHoursSpecification",
      "dayOfWeek": ["Tuesday", "Wednesday", "Thursday", "Friday"],
      "opens": "09:00",
      "closes": "17:30"
    },
    {
      "@type": "OpeningHoursSpecification",
      "dayOfWeek": "Saturday",
      "opens": "09:00",
      "closes": "14:00"
    }
  ],
  "sameAs": [
    "https://www.instagram.com/examplestudio"
  ]
}
</script>
```

BreadcrumbList for a key service page (page-level injection):

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "Home", "item": "https://www.example.com.au/" },
    { "@type": "ListItem", "position": 2, "name": "Services", "item": "https://www.example.com.au/services" },
    { "@type": "ListItem", "position": 3, "name": "Brow Lamination", "item": "https://www.example.com.au/services/brow-lamination" }
  ]
}
</script>
```

Product schema is generated by Squarespace Commerce for product pages. Do not
hand-write a second Product block unless you have confirmed the native one is
missing.

### FAQ schema

Google retired FAQ rich results on 7 May 2026. Do not add `FAQPage` markup for
rich results. Keep FAQ content (for example in an accordion block) as visible
on-page text.

## Images: Alt Text, Size and Format

### Alt text

- **Image blocks:** the image block's caption / alt field. On some designs,
  Squarespace uses the image's filename or caption as alt text if the alt
  field is empty, so rename files meaningfully before uploading.
- **Gallery sections and blocks:** each image has its own title/description
  used for alt text.
- **Products:** product image alt text is set on each product image.
- **Background images** in sections are decorative to assistive technology;
  do not put important information only in a background image.

### Format, size and lazy loading

Squarespace's image CDN generates multiple sizes of every upload and the
templates request an appropriate one with `srcset`, loading images lazily as
they approach the viewport. You cannot change this behaviour, but you can:

- Upload at around 1500 to 2500px wide and compressed (roughly under 500 KB
  for photos) rather than straight-from-camera files.
- Avoid huge PNGs for photographs; use JPEG and let the CDN handle delivery.
- Keep the first section light. A full-bleed video background is the most
  common Squarespace LCP problem.

## Security Headers

Squarespace controls response headers. The one security header you can
influence is HSTS:

- In the **SSL** settings, choose the **Secure** option (HTTPS for all
  visitors) and enable the **HSTS** option. This turns on
  `Strict-Transport-Security` for the site.

Everything else is platform-controlled:

```bash
curl -sI https://www.example.com.au | grep -Ei 'strict-transport|x-frame|content-security|x-content-type|referrer|permissions'
```

| Header | Status on Squarespace | Workaround |
|--------|-----------------------|------------|
| `Strict-Transport-Security` | Toggle in SSL settings | Turn it on |
| `X-Content-Type-Options` | Platform-controlled | None |
| `X-Frame-Options` / `frame-ancestors` | Platform-controlled | None |
| `Content-Security-Policy` | Not configurable | A meta CSP via code injection is possible in theory but will break Squarespace's own scripts and editor. Not recommended. |
| `Referrer-Policy` | Not configurable as a header | `<meta name="referrer" content="strict-origin-when-cross-origin">` in site-wide header code injection |
| `Permissions-Policy` | Not configurable | None |

**Cloudflare in front of Squarespace is not a supported workaround.**
Squarespace issues and manages SSL for connected domains and requires its
DNS records to point directly at Squarespace. Proxying through your own
Cloudflare (orange cloud) is not supported and commonly breaks SSL
provisioning. Keep records DNS-only.

**How FAT should score this:** credit HSTS if the toggle is on, mark the rest
as "platform-limited", and recommend the Referrer-Policy meta tag as the one
cheap improvement.

## Performance

Squarespace serves a fixed framework you cannot trim. Focus on additions.

1. **Code injection audit.** Review site-wide header and footer injection.
   Old tracking pixels, chat widgets and abandoned A/B testing snippets are
   common. Move anything non-critical to the footer.
2. **Third-party embeds.** Instagram feeds, booking widgets, review carousels
   and map embeds each load their own scripts. Replace live embeds with static
   images linking out where possible (a static map image linking to Google
   Maps is far lighter than an embedded map).
3. **Video backgrounds** in the first section. Swap for a still image on key
   landing pages.
4. **Fonts.** Squarespace loads every weight used across the site styles.
   Keep to two families and a small number of weights.
5. **Page length and block count.** Very long pages with dozens of sections
   and galleries are slow on mobile.
6. **Commerce pages.** Product pages with many variants and large image
   galleries benefit most from compressed uploads.

Measure with PageSpeed Insights on mobile, testing the home page, a key
service or product page, and a blog post.

## Search Console Verification

1. **Squarespace's built-in Google Search Console connection** (in the
   analytics or SEO area). It verifies the site and submits the sitemap.
2. **Domain property via DNS TXT record.** If the domain is managed by
   Squarespace, add the TXT record in the domain's DNS settings; otherwise add
   it at your DNS provider.
3. **Meta tag** via site-wide header code injection:

   ```html
   <meta name="google-site-verification" content="YOUR_CODE_HERE">
   ```

HTML file upload verification is not possible.

## What You Can't Fix on Squarespace

| Limitation | Detail |
|------------|--------|
| robots.txt | Not editable at all; only the AI-crawler toggle. |
| Canonical tags | Always self-referencing; no per-page override. |
| Response headers | Only HSTS is configurable. |
| Sitemap contents | Auto-generated; exclusion only by hiding pages. |
| Template code (7.1) | No template editing; only code injection and custom CSS. |
| URL prefixes | Collection item URLs follow platform formats (for example `/shop/p/slug` for products); blog post URL format is configurable within limits. |
| Collection filter URLs | `?category=`, `?tag=` and `?offset=` views always exist. |
| Web root files | You cannot upload arbitrary files to `/` or `/.well-known/`; uploaded files live under `/s/`. |
| Proxying / CDN | Cannot put your own CDN or proxy in front. |
| Code injection on entry plan | The entry-level plan does not include code injection. |
